# Правила проекта PCPulse

- Работа ведётся **напрямую в ветке `main`** (без создания отдельных веток и pull request).
- **Запрещено отправлять изменения в `main` без повышения версии приложения.** Единственный источник версии приложения — `<Version>` в `src/Directory.Build.props` (формат `MAJOR.MINOR.PATCH`). Перед каждым `git push` сравните её с версией в `origin/main`: новая версия должна быть строго выше (как минимум patch). Проверьте, что тег отсутствует и локально (`git tag --list v<новая-версия>`), и на GitHub (`git ls-remote --tags origin refs/tags/v<новая-версия>`). Правило действует для любого изменения проекта, включая только тесты, документацию и CI: workflow релиза запускает сборку и публикацию приложения при изменении версии. Если версия не повышена или тег уже занят — исправьте это до коммита и пуша.
- Версия пакета контрактов `PCPulse.Contracts` задаётся отдельно свойством `<Version>` в `src/PCPulse.Contracts/PCPulse.Contracts.csproj` (начальная — `1.0.0`). Повышайте её только при изменении публичного контракта: совместимые расширения меняют `MINOR`/`PATCH`, ломающие изменения — `MAJOR`. Не переиспользуйте существующий тег `contracts-v<версия>`.
- При изменении версий обновляйте `README.md`, если в нём указана текущая версия.
- **Обязательная проверка перед каждым пушем:** получите актуальное состояние (`git fetch origin`), проверьте статус последних запусков GitHub Actions для `main` командой `gh run list --branch main --limit 20` и убедитесь, что применимые Windows/Linux CI-проверки завершились успешно. Для неуспешного запуска изучите причину (`gh run view <run-id> --log-failed`), исправьте её и повторите локальные проверки; не отправляйте новый коммит поверх известной неисправности.
- GitHub Actions не может проверить ещё не отправленный коммит. Поэтому до пуша обязательно выполните локально `dotnet build PCPulse.sln -c Release --warnaserror` и `dotnet test PCPulse.sln -c Release`; при ошибке сначала исправьте её. После пуша дождитесь Actions именно для отправленного коммита и проверьте результат через `gh run list --branch main --limit 20` / `gh run watch <run-id>`. Убедитесь также, что workflow `Release PCPulse` успешно собрал и опубликовал релиз с тегом `v<новая-версия>`. Пуш не считается завершённым, пока CI не прошёл и новая версия не выпущена; при падении CI или релиза исправьте проблему, снова повысьте версию приложения, выполните локальные проверки и только затем отправляйте исправление.
- Все изменения в репозитории фиксируются локальным коммитом в `main` до выполнения `git push`.
